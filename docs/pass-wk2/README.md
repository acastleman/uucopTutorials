# PASS WK2 — Retrieval Practice, as a static page

Live: <https://acastleman.github.io/uucopTutorials/pass-wk2/>

A full reproduction of the PHRM 707 WK2 tutorial running as a GitHub Pages
static site instead of a Shiny app. Zero shinyapps.io instance hours.

Generated by `RMD/prototypes/static-tutorial/build_static.R` from
`courses/PHRM707_PASS/tutorials_flipped/02_retrieval_practice/`. **Do not edit
these files by hand** — re-run the converter.

## Why it looks right

It reuses the production files rather than imitating them:

| from the real tutorial | what it gives |
|---|---|
| `retrieval_practice_tutorial.html` (prerendered) | all prose, all 6 kable tables, all 31 sections, all 4 confidence checkpoints, learnr's own `.tutorial-question` placeholders |
| `www/uucop-tutorial.css` | the actual Union crimson design system, unmodified |
| `www/uucop-tutorial.js` | the actual header, title block, crumb and progress instrument |
| `#uucop-config` JSON block | header title, course, week, sidebar groups, 20/20 target |

The conversion is subtractive: strip the Shiny/learnr runtime, keep everything
else, and inject `uucop-static.js`. That file supplies only what Shiny used to —
a Shiny shim (every `Shiny.*` call in `uucop-tutorial.js` is already guarded),
question widgets rendered into learnr's existing placeholders using learnr's own
Bootstrap markup, and a `uucop_progress` message byte-compatible with what
`uucopTutorials::uucop_progress_push()` sends.

That last point matters: the header you see is driven by the same production
code path, `minutesInMs` countdown included.

## What it does differently, on purpose

**Time on task is ACTIVE time.** The Shiny build computes minutes as
`difftime(Sys.time(), session_start)`, so an idle tab accrues credit —
`progress.R:134` says as much. Here a second counts only if the document is
visible *and* the student interacted within the last 60 s.

**Events flush with `fetch(keepalive: true)` on `pagehide`,** which survives the
tab closing. A `later()` tick scheduled at disconnect on a suspended
shinyapps.io worker does not.

## Known gaps

- **No section sidebar.** learnr builds its `.topicsList` nav client-side, so
  stripping its runtime lost it. Every section is present, stacked in one scroll;
  what is missing is the navigation and progressive reveal.
- **No feedback form.** It posts email server-side.
- **Answered count is not seeded from the server** — it comes from
  `localStorage` plus the current session, so a second device starts at zero. The
  real version should seed from `rpc/uucop_progress`.
- **Nothing is recorded.** No Supabase credentials are configured here, so events
  queue in `localStorage`. Answer keys are visible in page source, which is
  expected: GitHub Pages cannot be access-controlled.
